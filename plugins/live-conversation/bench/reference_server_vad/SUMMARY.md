# Reference recordings: the bar

Deployment `gpt-realtime` over the Azure OpenAI GA realtime WebSocket (`/openai/v1/realtime?model=gpt-realtime`, api-version `v1`). `gpt-live-1` exists on the resource but rejects the realtime protocol (HTTP 400 `OperationNotSupported`), and the preview `api-version=...-preview` path returns `realtime_beta_access_required`.
Turn detection `server_vad`, input transcription `gpt-4o-mini-transcribe`, default voice `alloy`, server default instructions (no custom prompt). Mic fed in real time in 20 ms chunks; each chunk is sent when its last sample is captured.

Generated by `bench/reference_runner.py --summarize` on 2026-10-29. Runs live in `<scenario>/run<k>/`; `bench/runs/<date>-bar-rep<k>/` links them for `score.py` and `blind.py`.

## Per scenario

v2v columns include barge-in turns (measured after the interrupted reply stops). `endpoint` = `speech_stopped` arrival minus ground-truth speech end. `stt` = transcription completed minus speech end. `stop` = interrupting `user_speech_start` to the client flush (time the server's `speech_started` arrived), median. `cutoffs` = turn-end decisions inside the user's speech, summed over runs. `neg` = replies that began before the user finished. `overlap ms` = assistant audio above -45 dBFS while the user speaks in a non-barge-in turn, summed over runs (talking over the user after a false cut-off). `stopped_by_own_continuation` = the user's resumed speech flushed a reply that started at a false cut-off. A negative endpoint p50 means the first turn-end decision was a false cut-off. `words` = median words the assistant generated in the whole scenario.
